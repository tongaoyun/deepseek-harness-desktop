# 小胤桌面架构

小胤以 Qoder Work 为产品主线，以 Claude、Codex 的任务执行能力为目标，定位为有岗位能力的桌面工作助手。用户面向任务、专家套件和技能；底层负责工具执行、结果检查和成果交付，不把参照产品的界面入口拼成多个工作模式。

## 组件

```text
React 工作台
  │ Tauri Command / Event
Tauri 原生层
  ├─ ERP 登录、系统凭据和权限审批
  ├─ 本地文件、扩展安装、SQLite 和自动更新
  └─ Harness Host 与本地 IM 进程管理
  │ JSON-RPC 2.0 / stdio
DeepSeek Harness Host
  ├─ Skills、MCP、知识库和会话
  ├─ 文件、Office、Shell、Jobs、Goal 和 Computer Use
  └─ 钉钉 Stream、消息队列和任务接管
  │ HTTP(S)
控制中心
  ├─ Bootstrap、模型、扩展、知识库、记忆和审计
  ├─ 知识库索引 Worker（PostgreSQL 持久化队列）和 MinIO 制品授权
  └─ LiteLLM、ERP MCP 与 Nacos MCP Registry
```

桌面只访问 Bootstrap 下发的业务端点和制品 URL，不访问 Nacos、PostgreSQL 或 MinIO 管理接口。

## 运行链路

| 场景 | 链路 |
|---|---|
| 登录 | 钉钉扫码 → ERP WebView Cookie → 公司身份校验 → 桌面会话 |
| 对话 | 用户目标与工作区 → 能力快照 → Agent 按需加载 Skill、连接器和知识库 → 模型/MCP/本地工具 → 任务时间线 |
| 任务恢复 | Host 健康探测 → 失败分类 → 进程清理 → 新会话重试 |
| 本地文件 | 原生授权 → 任务目录 ID → Harness 文件或 Office 工具 → 本地预览和变更卡片 |
| 扩展安装 | 控制中心目录 → 制品下载 → SHA-256、Manifest 和路径校验 → 版本目录 |
| 连接器 | 员工启用与配置 → MCP 握手和工具清单诊断 → 每轮能力快照 |
| 定时任务 | 桌面本地计划 → 普通任务执行入口 → 独立对话、成果文件及运行记录；对话工具经 Host/Tauri 回到同一本地计划存储 |
| 钉钉 | DingTalk Stream → 本地队列和会话 → Harness；`/bind` 将会话绑定到桌面任务 |
| 审计 | 桌面或服务端 → 去敏事件 API → PostgreSQL |

## 能力矩阵

| 领域 | 能力 |
|---|---|
| 身份与模型 | ERP 扫码登录、控制中心模型目录、LiteLLM |
| 任务 | SQLite 会话、搜索、归档、流式回复、任务隔离的消息队列、取消、失败重试、产物和分组执行时间线 |
| Agent | 统一任务执行、Workspace Context、后台 Jobs、持久 Goal、最多 3 个并行子 Agent |
| Skills 与专家套件 | 自动匹配、`/` 显式调用、标准 SKILL.md/目录/ZIP/tar.gz 导入、岗位方案创作、定制副本和 ZIP 分享 |
| 连接器 | Streamable HTTP/SSE/STDIO、批量 JSON 导入、个人配置编辑与删除、工具发现、诊断和能力快照 |
| 本地工具 | 文件、DOCX、XLSX、PPTX、PDF、Bash/PowerShell、浏览器和 Computer Use |
| 知识与记忆 | 个人/团队/公司知识库、来源引用、记忆确认、分类管理、明确偏好自动记忆与按需读取；见 [记忆](memory.md) |
| 定时任务 | 本机时间计划、附件和任务上下文、对话创建及管理、执行记录；不依赖云端工作流 |
| IM | 钉钉 Stream、开放/配对模式、持久队列、任务接管、附件和产物回传 |

## 产品模型

| 对象 | 职责 |
|---|---|
| 任务 | 承载一次对话、工作区、附件、执行时间线、产物和恢复状态 |
| Agent | 规划并执行任务，按需调用工具、Skill、后台 Job、Goal 和子 Agent |
| Skill | 可复用的工作方法、领域知识和输出规范；运行时以 `SKILL.md` 为入口 |
| 连接器 | 通过 MCP 提供外部系统的工具和数据，不包含工作方法 |
| 知识库 | 提供可检索、可引用的长期业务上下文 |
| 定时任务 | 在本机按时间计划复用普通任务入口，保存运行记录和产物；管理端仅查看已上报结果 |
| 专家套件 | 将岗位场景、工作流程、交付标准、Skills、命令和连接器组织为完整工作方案，支持定制与团队分发 |

Agent 根据 Skill 描述自动匹配能力，也允许通过 `/` 明确调用 Skill、专家套件及套件命令。专家套件和独立 Skill 复用统一 Harness；套件没有独立执行引擎。显式切换套件或命令时重建会话并回放上下文，只加载选中命令的正文。

显式指定能力时，任务上下文要求先加载相关技能并读取工作方法与交付标准，套件 ID 不作为技能 ID。未指定能力也可以直接执行。知识库未指定且套件未限定范围时传递 `null`，表示在员工可访问范围内按需检索；明确空数组表示空范围，两者不混用。

Harness Host 的 `task-instructions.ts` 为桌面对话和本地 IM 每轮追加统一执行约定，约束澄清、用户意图、验证、失败调整和交付。`local_files_publish` 将实际存在的成果登记为可打开的文件；登记与文件修改回执独立，既不伪造改动也不声称已验证内容质量。服务端知识索引 Worker 只负责文档解析、分块和索引。

会话重建优先回放有界的实际文件与恢复状态，再补充可见对话；不是独立长期记忆服务。部分输出后报错和输出上限属于未完成状态。IM 使用已有持久队列保存执行阶段及送达进度，区分任务执行与网络发送重试；附件原件和完整文本缓存放在授权工作目录，通过已有文件读取工具分页。行为与限制见 [任务执行](task-execution.md)。

本地导入在暂存目录内转换标准 `SKILL.md`、`.claude-plugin/plugin.json`、`.qwen-plugin/plugin.json` 和 `.qoder-plugin/plugin.json`，自动补齐原生分发清单并保留资源路径。选择文件与安装分离，确认安装后才写入扩展目录。企业目录仍要求原生 Manifest 与精确版本、摘要。外部 MCP 配置按套件命名空间导入个人连接器；不支持的 Hooks、自定义 Agents、LSP 和 OAuth 配置明确报错。格式范围和操作流程见 [扩展使用](extensions.md)。

桌面对话统一使用 Agent 执行，不提供 Agent / Plan 模式切换。用户直接描述任务；仅需分析或方案时，在对话中明确要求。底层 Harness 保留内部 Plan 协议兼容，不作为桌面选项暴露。

运行中追加文字进入本机任务队列，当前轮成功后按顺序续轮，沿用该任务的上下文与模型。失败、停止和重启恢复后队列暂停；切换页面不影响后台续轮，也不覆盖其他任务的草稿。执行过程将连续工具事件分组，成功组默认折叠，错误与确认独立显示。当前轮完成或停止后默认收起过程，保留正文与成果。原生任务在初始化前登记取消状态；停止终止任务进程组，前端忽略后续事件并阻止自动重试，不将取消显示为模型错误。行为和限制见 [任务执行与结果展示](task-execution.md)。

桌面对话、定时任务与 IM 接管任务统一运行在本机 Harness，可使用本地文件、技能、员工连接器、浏览器和 Computer Use。服务端知识索引 Worker 只处理文档解析、分块与索引，不执行另一套云端 Agent。

## 界面与交互

`XiaoyinMascot` 使用参考应用的绿色身体 GIF，专家套件叠加手部动图；技能和连接器使用原始场景 SVG。图片独立加载，不引入额外动画引擎；系统减少动态效果时使用静态矢量替身。来源与使用范围见 [形象规范](brand.md)。

四类扩展页通过 `CapabilityHero` 使用 144px 横幅；知识库在窄窗口下可随文案增高。专家套件每 5.5 秒切换场景，支持手动选择，悬停/聚焦暂停；专家套件与技能的创建入口位于顶部「添加」，横幅不重复放置。技能采用三个重叠插画入口，绑定真实目录条目。知识库的 `KnowledgeHeroArt` 使用 SVG 与 CSS 展示阅读、扫视和翻页，遵循减少动态效果设置。`CatalogLoading` 提供首次加载骨架，刷新已有列表时保留卡片。

桌面使用白色工作区、浅灰侧栏、灰色导航选中态和黑色主按钮；绿色用于启用状态与输入框聚焦反馈。文本、边框、背景和阴影通过 `src/styles.css` 的 `--xy-*` 变量统一。对话正文与输入框为 14px，目录卡片说明为 12px，状态信息保持次要层级。

侧栏将专家套件、技能、连接器和知识库作为独立入口，扩展分组可收起；当前任务保持选中反馈。目录内容最大宽度为 790px，搜索、刷新和添加操作固定在顶部。套件两列、市场技能三列展示；本机与已安装技能为带使用按钮和开关的单行列表。窄窗口自动减列，分类条支持按钮和横向滚动。

技能和套件详情在主工作区内展开，侧栏持续可用；顶部提供返回、安装、打开目录、定制副本、ZIP 分享、聊天启停和对话入口。`read_extension_contents` 读取已安装包的 README、技能和命令原文；套件内文档通过弹窗查看。连接器详情采用居中弹窗，原文与连接器弹窗支持键盘焦点约束和返回入口。

`set_extension_enabled` 在扩展 ID 目录使用 `.disabled` 标记持久化设备级启停，独立于版本；版本更新保留设置。目录清单返回 `enabled`，前端能力快照、`/` 候选和原生 Harness 加载共同排除停用扩展。已启动的 Harness 会话不热卸载技能，新会话使用当前设置。`reveal_extension_directory` 打开经过校验的安装目录。

`TaskComposer` 独立管理输入框、能力选择、正文 `/` 和 `@` 候选、附件预览与最近目录菜单。输入框随内容在 64–220px 之间伸缩；Enter 发送、Shift+Enter 换行，中文输入法确认不发送，候选菜单打开时优先选择。⌘/Ctrl+N 打开新任务草稿，⌘/Ctrl+K 搜索任务。

`taskDrafts` 按员工和任务持久化未发送内容与上下文引用。App 在切换前保存、恢复后再启用自动保存，以任务上下文代次丢弃过期异步结果。`import_pasted_image` 将 PNG/JPEG 存入本地应用数据目录并返回标准附件引用；工作目录和附件根路径用于重启恢复。连接器选择进入能力快照，套件/技能选择进入 Harness 的 `selectedExtension`，不增加第二套执行流程。完整约束见 [任务执行](task-execution.md)。

页面采用 180ms 淡入，菜单采用 120ms 淡入与轻微位移，侧栏宽度切换采用 180ms 过渡。技能插画卡片悬停转正，专家横幅使用轻量标签位移和 GIF 动画；遵循系统减少动态效果设置。完整参考对照与未实现项见 [桌面能力对照](desktop-alignment.md)。

## 连接器管理

连接器页面区分目录状态、员工启停和最近一次实际检测结果。开关启用不等于连接成功；配置变更会使旧检测结果失效，迟到的结果不会覆盖新配置。个人连接器关闭后仍保留在「已添加」中。

`connectorImport.ts` 将 MCP 配置解析为逐项结果，保留显示名称并生成稳定 ID。批量导入依次等待每项持久化，分别报告错误，拒绝覆盖已有 ID。个人配置由员工本机存储提供；企业目录缓存不保存个人配置，删除后不会由旧目录缓存恢复。

「手动填写配置」和「编辑配置」使用独立 MCP 表单，不经过企业发布流程。STDIO 填写完整命令，按引号拆分程序与参数，不通过 Shell 执行；HTTP/SSE 填写地址和请求头。环境变量与请求头以键值行编辑，保存失败保留表单，编辑保留原启停状态。`timeoutSeconds` 默认 60 秒、范围 1–600 秒，传至原生能力快照和 MCP 执行层，约束任务中的连接、工具列表获取及调用。目录健康检测仍使用独立的短时检测预算。检测通过 Harness 建立 MCP 连接并发现工具；桌面内置连接器不伪装成已通过 MCP 检测。

## 平台支持

| 平台 | 构建 | 发布方式 | 限制 |
|---|---|---|---|
| Windows x64 | Windows Runner | MSI、NSIS、Tauri Updater | 安装包不含 Authenticode 签名 |
| macOS arm64 | `macos-arm64` Runner | 临时签名 DMG、签名更新包、独立 Mac 更新索引 | 不含 Apple 公证，真实升级待验收 |
| macOS x64 | `macos-arm64` Runner 交叉构建 | Intel DMG 与签名更新包 | 本机构建需 Rosetta；Intel 实机安装升级仍需验收 |

Computer Use 依赖可交互桌面，不在锁屏会话或 Windows Session 0 中运行。ERP MCP 工具为只读工具。IM 支持钉钉；飞书、Lark、微信和企业微信不在桌面连接器列表中。

macOS 14+ 使用随 Harness 打包的 Swift 桌面助手，复用 `computer_use_observe/click/type/key/scroll` 接口。观察主显示器截图与前台应用辅助功能元素；点击坐标使用最近截图的像素坐标，`WIN` 修饰键映射 Command。每次操作返回新的观察；观察失败时可能已发生操作，需要先重新观察，不能盲目重试写入。

辅助功能遍历优先读取焦点元素和焦点窗口，再按层级扩展、去重；元素数、深度、总节点数与时间均有上限，避免文件列表占满结果后遗漏当前弹窗。`G`、`L` 按键支持前往路径和地址栏等应用快捷键。

Mac 桥接在操作前要求已有成功观察，并校验前台进程、窗口标题/位置/尺寸和截图尺寸。观察之后切换应用、移动窗口或改变显示尺寸时，拒绝旧坐标操作；失败使已有观察失效，下一操作需先重新观察。这是动作开始前的状态校验，不是对整个外部应用的锁定，也不保证应用在动作执行中不会自行变化。

macOS 需要用户在系统设置中开启辅助功能和屏幕录制权限；代码不自动授予权限。助手按构建机器架构编译并临时签名，开发环境由 `pnpm build` 生成，正式安装包由 macOS 打包脚本复制到运行时资源。当前实现不覆盖多显示器联合桌面或锁屏操作；编译和协议测试通过不等于真实应用交互已验收。

## 成果结构与页面检查

`office_document_check` 只读检查 DOCX、XLSX、PPTX、PDF。表格报告工作表、已检查单元格、公式数、错误单元格及缺失缓存计算结果，最多扫描 100000 个非空单元格、返回 100 项问题；明确标记截断。公式值使用实际结果字段，保留 0 和 false。工具不重算公式，也不验证业务逻辑、图表或版面。

`office_pdf_page` 将指定 PDF 页渲染为图像并加入真实工具结果，支持具备图像能力的模型查看扫描内容和版面；每次一页，宽度 1400 像素，文件上限 25 MiB。Office 版面通过 `office_document_export_pdf` 导出 PDF 后查看；没有相应应用或图像模型时明确说明，不能声称完成视觉验收。结构检查与页面渲染不替代最终内容验证。

`office_engine_status` 检测本机 LibreOffice。`office_document_export_pdf` 支持 DOCX、XLSX、PPTX 导出 PDF；`office_xlsx_recalculate` 使用独立 LibreOffice 配置强制重算 XLSX 并保存副本。工具参数为 `rootId`、源文件 `path` 和新文件 `outputPath`，不覆盖原文件或任何已有目标。工具返回结构检查结果、实际文件路径和哈希，桌面及 IM 按新成果识别。

表格创建、单元格修改、追加行和新增工作表共用单元格输入：普通数值/布尔/文本/空值，或显式 `{"formula":"C2*D2"}`。公式不接受调用方提供缓存结果；以 `=` 开头的普通字符串仍按文本保存。写入后设置打开时重新计算，但只有真实重算引擎完成后才存在可验证的计算结果。简单表格无需安装 Python 或 openpyxl。

XLSX 读取将缺失单元格明确转为空文本，保持列位置且返回无稀疏数组的 JSON；公式结果 `0`、`false` 不丢失，富文本按所有文本片段顺序拼接。DOCX、PPTX、PDF 检查结果只返回该格式存在的页数/幻灯片字段，不传递 `undefined`。桌面预览按单元格坐标补齐空列，缺少缓存的公式显示“待重算”，不以空白或错误列位置展示金额。

`office_xlsx_format_sheet` 调整已有工作表的列宽、文本换行、估算行高和 A4 打印范围；内容按一页宽打印，纵向允许分页。保留值与公式，写入前保存可撤销备份，并接入普通文件改动及成果卡片。支持最多 2000 行、100 列，不自动处理合并单元格；过长内容须先拆分为多行。行高估算不替代导出后的视觉检查。创建表格的自动列宽计算补齐稀疏位置，中文按双字符宽度估算。

转换使用 [LibreOffice 官方命令行参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html) 的 headless、独立用户配置与指定输出目录，不接入员工正在使用的 Office 会话。单文件输入和输出上限 25 MiB，超时 90 秒；取消或超时停止转换进程树，清理临时配置和中间文件。成功退出但没有实际结果仍视为失败。最终文件写完后独占发布，不登记半成品；目标目录需支持硬链接。

含宏或外部工作簿链接的文件不自动转换，需在办公应用中处理。公式重算测试覆盖过期缓存、缺失结果、0 和 false；这不保证 Excel 专有函数、数据连接、复杂图表或字体排版完全兼容。生成 PDF 后仍需查看页面并核对业务内容。

LibreOffice 为可选本机依赖，不随小胤安装包内置，使用[官方下载页](https://www.libreoffice.org/download/)选择对应系统和芯片版本。按 `XIAOYIN_SOFFICE_PATH`、系统标准安装目录及 PATH 查找；显式配置不可用时不悄悄换用其他程序。Mac 支持 `/Applications/LibreOffice.app` 和用户 `Applications/LibreOffice.app`，Windows 支持 `Program Files` 与 `Program Files (x86)` 下的 `LibreOffice/program/soffice.com`。安装到标准目录后下次检测即可识别；环境变量应进入小胤/Host 进程，单独写入 Vite 的 `.env.local` 不代表原生进程已读取，修改环境配置后需重启。

macOS 后台转换使用临时 [Fontconfig 配置](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html)加载系统、全局及用户字体目录，避免只使用 LibreOffice 自带拉丁字体而缺失中文；配置与缓存随转换临时目录清理，不修改系统设置或源文档字体。已有 `FONTCONFIG_FILE` 设置时沿用调用方配置。中文输出需本机具备中文字库，可使用开源 Noto Sans CJK SC。引擎缺失仅影响重算与 Office 转 PDF，普通文档和表格生成仍可使用。

## 安全规则

- 企业原生套件和 Skill 引用连接器 ID、工具和知识库。外部本地套件可以附带 MCP 配置，转换后存入个人连接器配置；已有同 ID 配置保留，凭据不回写到套件文件。
- 每轮只加载员工启用、目录可用且必填配置齐全的连接器；配置就绪与实时连接成功分别展示。能力快照在轮次提交时固定，下一轮重新采用当前配置。
- 本地工具只访问任务授权目录，并拒绝目录穿越、越界符号链接和敏感文件。
- 删除、高危 Shell 和破坏性 MCP 调用必须经过原生确认。
- 模型凭据、员工令牌和 IM Secret 只进入受控进程或系统凭据库。
- UI、设备报告和审计不保存隐藏推理、工具参数、业务原文、令牌或绝对路径。
- ERP Cookie 只保存在系统 WebView 中，不进入 Harness 或控制中心。
