# 发布验收

每次发布记录版本、提交、环境、实际结果和报告路径。使用合成员工及临时资料，测试结束清理数据，凭据不写入报告。

## 代码检查

```bash
pnpm check
```

桌面端“本地能力 → 高级设置与诊断 → 导出诊断”只生成版本、能力状态和时间戳，用于提交安装或运行时问题；它不包含 Prompt、Session 正文、本机路径、Token 或任何连接器凭据，也不能用于恢复会话。

诊断导出只接受内置能力名称及受限格式的 Runtime/版本标识。Harness Host 的 JSON-RPC 错误和 stderr 在跨进程前统一移除环境凭据、Bearer Token、常见密钥格式及控制字符，并限制长度；各模型与连接器适配仍须在来源处先做领域化错误归类。

检查覆盖版本、lint、类型、前端与 Host 测试、生产构建、Harness 运行时和契约验收、Rust 格式、Clippy 与测试。服务端在其仓库执行 `sh scripts/check.sh`。

Gitea CI 的 Web/Host Job 执行 `pnpm check:web`；Windows Job 检查 PowerShell 与 Rust。安装包工作流只负责构建、签名、包内烟测和发布身份校验。

安装包中的本地文件、Office、Shell 和 Computer Use 自测可另外运行：

```bash
node scripts/check-harness-runtime.mjs "$(command -v node)" harness-host --self-test
```

健康响应中的官方能力来自实际安装的依赖闭包（包括 `dsh` 的间接依赖），因此依赖缺失会显示为“未配置”或在初始化阶段失败，不会被静态清单掩盖。

## 服务端

开发环境：`http://192.168.2.67:30081`。`xiaoyin-server` 每个副本提供 API、控制台及知识索引，发布流水线等待目标镜像全部副本就绪。

| 项目 | 必须验证 |
| --- | --- |
| 基础接口 | 健康、Bootstrap、模型与能力目录、分页和权限 |
| 业务状态 | 审计、记忆版本冲突、图文反馈及原图读取 |
| 知识库 | 上传、排队、索引、来源回读、重建、删除、替换、无证据及失败重试 |
| 管理端 | 静态资源、真实数据、筛选搜索、反馈和知识库操作 |
| 性能 | API 延迟与错误、索引完成量、队列排空、内存和测试数据清理 |

中文 DOCX、公式 XLSX、文本 PDF 和无文字层扫描 PDF 分别验证。扫描件核对图像、OCR 内容与页码，不能仅检查索引 READY。

## 任务与会话

`pnpm check:web` 包含 Harness Profile 启动、技能与结果契约、模型工具权限及 Session Query 多进程验收；这些使用隔离临时目录和模拟模型，不代表外部业务系统已通过。

- 钉钉官方 OAuth 自动登录、退出重启、会话到期、网络恢复和休眠唤醒。
- 原任务恢复后核对会话 ID、工作目录、附件与文件哈希。
- 停止后进程退出，保留部分输出，迟到事件不改回成功。
- 失败、停止和重启后的消息队列保持暂停，恢复只执行一次。
- 保存失败明确提示，重试保存不重复执行任务。
- 钉钉分别核对任务执行和成果送达，重试不重复发出已送达文件。

## 真实任务

`pnpm evaluation:run` 执行代码恢复、表格重算、文档生成和缺参澄清。检查源文件保留、真实工具调用、结构化结果和实际交付物，运行说明见 [任务评测](task-evaluation.md)。

合成样本、包内能力烟测和真实业务验收分别记录。扩充低清扫描、复杂 Office、多文件长任务和真实业务数据集后，再评估生产成功率。
