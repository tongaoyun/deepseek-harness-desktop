# 产品知识库引用

## Change

技能、内置技能与专家套件清单的 `knowledgeBaseRefs`、创建草稿、发布准备及详情解析统一接受 `personal:<key>`、`department:<key>`、`company:<key>`，与知识库目录的 `reference` 相同。移除 `team:`、`organization:` 的接收和自动转换。

发布评估按配置公司的实际归属键检查公司知识库；个人和部门依赖继续在任务准备及执行时按认证员工校验。引用不是授权，开始后的任务仍使用固定知识库 ID 及不可变内容。

## Migration

1. 先更新服务端，再更新桌面和扩展发布工具，避免新桌面的部门或公司引用被旧服务端拒绝。
2. 对使用旧前缀的个人扩展或待发布制品，从实际可见目录选取当前 `reference`，更新对应技能及顶层依赖并集，创建新版本。不要改写已发布制品、会话或执行快照。
3. 使用旧引用的未保存创建草稿须在对话中重新创建；不读取或转换旧草稿协议。
4. 验证个人、部门、公司依赖可保存和解析，旧前缀明确拒绝；套件准备将依赖固定到实际知识库 ID，无权或歧义不会扩大检索范围。
