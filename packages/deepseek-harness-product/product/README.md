# 企业产品协议

## Summary

协议包只负责钉钉身份、连接器目录与授权、组织知识库、反馈和服务端访问，不依赖 Harness 或 Electron。

主进程通过命名空间桥校验 `protocol` 白名单，员工令牌和连接器私密配置不会返回渲染进程。`connector-draft` 出口提供连接器表单、配置模板、重连结果及写入回执校验。保存、删除和审核只在回执身份与版本匹配后更新界面；失败保留编辑内容。

`catalog` 出口统一校验公开目录与工具元数据。目录项必须有服务端 ID 和名称，重复 ID、损坏条目或未知工具读写权限均报错，不返回部分列表；工具没有展示名时使用原名。主进程沿用同一工具校验，不隐藏无效工具声明。

`tasks.capabilities.read/prepare` 仅处理执行模式和任务知识库 ID，跨进程请求、读取结果及准备回执共用 `protocol` 的运行时校验和推导类型，拒绝过时字段及损坏回执。准备回执须与显式选择一致，且每个知识库都通过依赖检查；显式恢复可移除失效知识库。校验失败不切换任务、不清空草稿；已开始任务的选择变更通过官方 Session 边界创建新任务。未选择知识库时不注册检索工具，不能扩大为空范围检索。

目录缓存仅用于连接器展示；直接传递服务端状态，不生成额外的可用性状态。知识库读取及工具执行重新检查服务端权限；连接器调用按 ID 查询当前配置，不遍历全目录。目录重置、员工切换和释放会取消即时读取及后台刷新，迟到结果不能返回或写入缓存；释放等待所有请求实际结束，释放后拒绝读取缓存。

公司内容通过 `content.submissions.inspect/submit` 校验并提交单个原生资源，身份和取消信号由主进程持有，不接收所有者声明。审核状态只读取摘要，完整内容通过详情读取。内容校验在落盘前拒绝文件与目录路径冲突，以及同一父目录的大小写别名；认证 API 不跟随重定向、不自动重发写请求。

公司技能使用 YAML 1.2 解析元数据，名称与目录一致，简介为非空单行字符串；拒绝损坏或重复字段、未知标签、别名、超过 64 层的嵌套及无效调用声明，避免发布成功后被原生 Provider 忽略。专家仍沿用原生插件的单行字段格式。AI 发布工具分发包含 YAML 实现与许可证的独立校验产物，无需安装依赖。

公司目录源的读取、刷新和会话版本检查均可接收调用者的取消信号；目录刷新只释放该调用者的等待，主进程继续管理共享同步。

## Model Experience

### Enterprise capabilities

#### What the model sees

本包不直接组装模型输入；运行时负责记录 `MCP` 连接器工具和知识库检索结果。

#### Token effect

协议和界面本身不增加模型 Token。

#### KV Cache effect

不管理模型缓存；工具及检索内容的变化由官方模型请求组装处理。

## Known Limitations and Deferred Work
<a id="known-limitations-and-deferred-work"></a>

- 企业服务需要有效员工身份及可访问的组织服务；第三方专家和技能插件使用其自身的管理入口。

产品桥接不提供 `native.*` 方法。安装标识与健康检查仅供桌面主进程的设备上报和反馈使用，不向页面暴露原始安装标识。[sidecar 协议](../../../native/deepseek-harness/README.zh.md)由产品维护。
