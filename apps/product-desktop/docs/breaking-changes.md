# 产品当前边界

本页只记录当前实现中容易影响开发和运维的约束。产品使用 DeepSeek Harness 原生 Agent、Skill Provider、Session、MCP 客户端和审批能力；产品代码只负责企业身份、公司内容、连接器、知识库和桌面交付。

## 专家与技能

- 专家套件和技能随桌面源码固定装配，左侧“扩展能力”直接打开；不提供独立安装、卸载、更新或设置重复页。
- 专家使用 Harness 的 `startActivation`、子 Agent 注册点和 Agent Team；技能使用 Harness 的 Skill Provider。产品不维护旧的 `start`、`persona/toolFilter`、独立插件更新或自定义执行循环。
- 页面分为“市场”和“我的”。市场只显示服务端审核发布的公司内容；个人专家、专家团和技能在“我的”管理，可提交发布。
- 公司专家团必须携带主理人规则、成员分工和全部成员说明，发布后按公司内容版本同步。市场内容只读，复制到“我的”后才能修改。
- 个人内容、官方 Session 历史和草稿分别由 Harness 的 Settings、Skill Provider 和 Session 持久化负责；内容版本变化不会改写旧会话。

## 公司内容同步与发布

- 桌面启动或进入专家套件、技能页面时读取本地目录，并在后台检查服务端发布包。成功检查默认 60 秒内不重复请求；失败保留最近一次有效目录。
- 发布包按资源摘要校验后原子更新。目录缺失、摘要不匹配、路径冲突和大小写别名都会拒绝安装，不会猜测或补齐文件。
- 管理员在控制中心逐项审核和发布。AI 发布使用仓库内的 `harness-company-publish` 技能，流程为 `check`、`plan`、`publish`；普通使用人员不需要发布权限。
- 服务端必须先提供 `/api/v1/company-content`，桌面才会同步公司内容。公司目录为空时，个人内容仍可使用。

## 连接器

- 企业连接器由官方 MCP 客户端加载。模型通过 `connector_search_tools` 按业务词发现工具，技能或专家可用 `connectorId` 和 `toolNames` 精确引用。
- 工具定义按连接器版本和哈希固定到 Session。连接器启动失败只隔离对应连接器，不阻塞普通对话；WRITE 工具继续使用 Harness 的审批和实时权限检查。
- 连接器目录、公司内容和知识库权限由服务端校验，桌面不信任任务快照中的员工或部门声明。

## Session 与知识库

- Session 只写当前 Harness 格式；受支持的旧格式由官方持久化目录迁移，未知事件或损坏记录明确拒绝。
- 公司内容、连接器定义和知识库范围在任务绑定时固定。固定内容缺失或哈希变化会阻止继续执行，并保留历史记录和诊断信息。
- 知识库检索范围只允许员工本人、直属部门和配置的公司范围。浏览文件不会自动把知识库加入任务。

## 开发与交付

- 产品仓库支持破坏性重构，不提供已删除产品协议、旧自建套件接口或旧缓存的兼容层。需要保留的数据由 Harness Session 和服务端迁移负责。
- `verify:upstream`、类型检查、聚合产品测试、桌面构建和安装验收是交付门禁。重复代码扫描用于人工审计，不因 fixture、平台变体或上游内容产生的少量重复阻断 CI。
- 桌面打包使用 Node、pnpm 和 Rust 缓存；源码检查只在 preflight 执行一次，平台矩阵专注构建、签名和安装验收。
- 当前固定 Harness 基线为 `dsh-v0.2.2-alpha.2`。修改上游同步模块时同时更新 `upstream.json` 和补丁清单，并运行 `verify:upstream`。
